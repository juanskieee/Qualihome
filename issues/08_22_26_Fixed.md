# 08/22/26 Issue Fix — Summary of Changes

All issues from `08_22_26.md` have been implemented and verified. Below is a per-issue summary of the fixes.

## 🛠️ ADMIN SIDE

### Issue 1 — Add New Project: Remove Location Fields ✅ Fixed
**Templates (`app/templates/dashboard/admin.html`)**
- Removed the Region / Province / City/Municipality / Barangay selects (and their hidden code/name inputs) from the **Add/Edit Project** modal. The project form now contains only: Project Name, Description, and Images.

- The geo fields now live in the **Add Subdivision** form — its PSGC selects were **enabled** (previously `disabled` + auto-derived from the parent project) and wired to the full Region → Province → City/Municipality → Barangay cascade (`initSubdivisionPsgc` rewritten in `admin_dashboard.js`, mirroring the previous project-cascade logic).

**Backend (`app/main/routes.py`)**
- `admin_edit_project` now preserves a project's existing geo columns when the form no longer sends them (new `geo_provided` guard), so old records aren't wiped on edit.
- `admin_create_project` / `admin_create_subdivision` already tolerate empty geo; no other backend change needed.
- Note: existing projects keep their stored location; new projects are created without location (subdivisions carry it).

### Issue 2 — Delete Project Broken + "Delete undefined?" ✅ Fixed
**JS (`app/static/js/admin_dashboard.js`)**
- Root cause: the shared `.sub-delete-btn` click handler read only `dataset.subId`/`dataset.subName`, but project cards emit `data-project-id`/`data-project-name`/`data-has-subs` — so the confirm dialog rendered `Delete "undefined"?` and silently aborted before any fetch.
- Handler is now entity-aware:
  - Reads `data-project-id || data-sub-id` and `data-project-name || data-sub-name`.
  - Blocks deletion client-side when `data-has-subs="true"` (projects) or `data-has-props="true"` (subdivisions) via `showToast()` warning.
  - Confirm posts to the correct endpoint: `/admin/project/<id>/delete` (which existed at routes.py:1854 but was never called by any JS) vs `/admin/subdivision/<id>/delete`.
  - DOM cleanup generalised: removes the matching card column and shows the correct empty state for `#projectsGrid` or `#subdivisionsGrid`.
  - Toast messages are now entity-accurate ("Project deleted…" vs "Subdivision deleted…").
- The preview-modal delete button (`projPreviewDeleteBtn`) proxies into the same handler and therefore works too.

### Issue 3 — Model Listing: Move Subdivision Dropdown ✅ Fixed
- In the **Add Model Listing** modal (`#adminCreatePropertyModal`), the Subdivision select was moved up to sit **directly after Model Name**. Field order is now: Model Name → Subdivision → (auto-derived geo) → Full Address → Model Type → Unit Type → …

### Issue 4 — Street / Block / Lot Combined into One Address Field ✅ Fixed
- Both Add Model Listing and Edit Property modals replace the three Street/Block/Lot inputs with a single **"Full Address (Street / Block / Lot)"** text input.
- Implementation: the visible input feeds hidden `street` / `block` / `lot_no` fields via a `_splitFullAddress()` parser (extracts `Block X`, `Lot Y` tokens; everything else becomes the street). All downstream logic — location composition (`_compose_full_location`), per-subdivision duplicate detection (`_find_property_with_same_block_lot`), and live duplicate checks — continues to work unchanged because it reads the hidden fields.
- Edit modal populate composes the display string back from the three DB columns.

### Issue 5 — Comma Formatting on Pricing Fields ✅ Fixed
**Shared helper (`app/static/js/main.js`)**
- Added `sqhCleanNumeric()` (strips commas/spaces/₱), `sqhFormatNumericValue()` (groups integer digits by 3, preserves one decimal point), and `sqhBindNumericFormatting()` which binds any `input[data-commas]` with caret-stable formatting on every keystroke. Auto-bound on `DOMContentLoaded`.

**Templates (`app/templates/dashboard/admin.html`)**
- 27 inputs converted from `type="number"` to formatted text inputs (`data-commas`): Total Selling Price, Promo Discount %, Reservation Fee, Downpayment % + Terms, Loanable %, VAT %, LMF %, Annual Interest Rate, Floor/Lot Area (Add + Edit property modals), Gross Monthly Income, C5.0 training-data gross income / monthly loans (+ edit variants), and min gross income criterion.
- Bedrooms/bathrooms/storeys and non-peso counters remain plain number inputs.

**JS (`app/static/js/admin_dashboard.js`)**
- Create-property submit uses a local `num()` wrapper (comma-stripped) for all numeric FormData appends; pricing-preview query params are stripped as well.
- Edit-property save strips commas for all numeric fields.
- C5.0 add/edit record payloads, their validators, and the criteria-save payload strip commas before `parseFloat`.

**Backend (`app/main/routes.py`)**
- New `_clean_numeric_str()` normalizer applied in `agent_submit_property`, `agent_edit_property`, `/admin/property/pricing-preview`, and both C5.0 training-data endpoints — comma-formatted values can no longer cause `Invalid numeric field` 400s even if submitted raw.

### Issue 6 — Manual Unit ID Entry ✅ Fixed
- `acp_unit_id` (create) and `ep_unit_id` (edit) are now editable text inputs (placeholder `e.g. TH-101`); removed `readonly disabled` + `sqh-disabled-field` styling and the "Auto-generated after save" placeholders.
- Backend: create route reads form `unit_id` and validates global uniqueness via new `_find_property_with_unit_id()` (409 with the conflicting model's name); falls back to the legacy `U######` generator only when blank. Edit route accepts a changed unit id (case-insensitive uniqueness check excluding itself) or keeps the existing value; backfill generator still applies when empty.

### Issue 7 — Peso Sign `?` → `₱` ✅ Fixed
- Byte-level audit confirmed files are clean UTF-8; the bug was literal ASCII `?` characters used as currency symbols. All 10 occurrences replaced with `&#8369;` (matching each file's dominant convention):
  - `admin.html`: lines 2524, 2672, 3494, 3866, 3867, 3926, 3927 (dashboard price cells, model-card price, Max Loanable, C5.0 Training Data & Historical Buyer income/loans columns).
  - `client.html`: price-filter options ("Below ₱3,000,000", etc., lines 3287–3289 — agent.html already had them correct).
- `client_dashboard.js` `fmtMoney` switched from `'PHP '` prefix to `\u20B1` (₱), matching that file's existing convention.

- Styling reuses existing semantic badge variants only (`badge-qualified` / `badge-conditional` / `badge-not-qualified` from `main.css`) — thresholds mirror the sim badges introduced on model cards (High ≥ 0.70, Moderate ≥ 0.40), keeping one canonical tier scale across the system. No new CSS.
